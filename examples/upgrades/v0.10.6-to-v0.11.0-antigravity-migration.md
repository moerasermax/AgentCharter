> **適用**：採用方專案 charter_version 在 `0.10.6` 範圍、使用 Gemini CLI（免費 / Pro / Ultra tier）作為 PM vendor、要升到 `0.11.0`（Antigravity CLI vendor）
> **核心改動**：(1) Gemini CLI vendor 棄用觸發 vendor 換手（dogfood signal #60 LIVE）+ (2) `roles/pm/antigravity-cli.md` v1.1 path A AI-DRAFTED + 同日 LIVE 第二輪校正接入 + (3) `roles/pm/gemini-cli.md` 標 LEGACY_AUTO_IMPORTED
> **預估時間**：15-25 分鐘（含 Antigravity CLI 安裝 + skill 手動轉換）
> **向下兼容**：⚠️ **部分相容** — 採用方若在 OSS / Enterprise / 付費 API key tier 可繼續用 Gemini CLI、本 walkthrough 可選擇性跳過；若在免費 / Pro / Ultra tier、**6/18 前必須遷移**

## 5. 🔥 手動轉換 charter slash command 為 Antigravity Skill

依 `roles/pm/antigravity-cli.md §3.6` LIVE 第二輪校正紀律 — 必須**手動建立** Skills `.md` 檔到 `~/.gemini/skills/<name>/SKILL.md`（**子目錄結構** + frontmatter `name:` 必填、全域 only、無 workspace 級）。

### 5.1 建 `~/.gemini/skills/` 目錄（若不存在）

```bash
mkdir -p ~/.gemini/skills
```

### 5.2 對 AI（Antigravity CLI session）下 prompt

```
請依 ~/.agentcharter/roles/pm/antigravity-cli.md v1.1 §3.6 「從 Gemini CLI legacy 遷移：手動轉換」段、把以下我既有的 `.gemini/commands/*.toml` 全部轉換成 Antigravity Skill `~/.gemini/skills/<name>/SKILL.md`（**子目錄結構**）：

1. `.gemini/commands/pm-init.toml` → `~/.gemini/skills/pm-init/SKILL.md`
2. `.gemini/commands/checkpoints.toml` → `~/.gemini/skills/checkpoints/SKILL.md`
3. `.gemini/commands/charter-init.toml` → `~/.gemini/skills/charter-init/SKILL.md`
（採用方 list 你實際有的 toml 檔）

轉換規則（§3.6 LIVE 第二輪校正）：
- 為每個 skill 建子目錄 `~/.gemini/skills/<name>/`
- 子目錄內檔名固定為 `SKILL.md`
- frontmatter **必含** `name: <skill-name>`（對應子目錄名）+ `description: "..."`
- TOML `description = "..."` → YAML frontmatter `description: "..."`
- TOML `prompt = """ ... """` 多行字串 → Markdown body 純文字（去掉 `"""` 包裹）

轉換完成後逐一回報每個新 Skill 路徑 + 一行內容摘要。
```

驗收：

```bash
ls -la ~/.gemini/skills/
ls -la ~/.gemini/skills/pm-init/
```

預期看到對應子目錄 + 內含 `SKILL.md`。

### 5.3 原 `.gemini/commands/*.toml` 不刪

對齊 `roles/pm/gemini-cli.md §9.3` LEGACY 紀律「不刪 = 培養魚塘」精神 — 原 toml 檔保留作為歷史 audit trail。

## 常見問題

### Q1: 我有兩個專案、都用 Gemini CLI、要每個專案重跑本 walkthrough 嗎？

**Step 2-3（安裝 `agy` + auth）**：一次性、全 user 共用、不重跑

**Step 4-5（plugin import + skill 手動轉換）**：因為 Antigravity Skills 是 **全域 `~/.gemini/skills/<name>/SKILL.md`**（子目錄結構、無 workspace 級、LIVE 第二輪校正）— 所有專案共用同一份 PM init skill。**只需第一個專案跑一次**、其他專案的 `~/.gemini/skills/` 已有對應 skill 子目錄可直接用。

**Step 6（MCP）**：若 workspace 級 → 每專案改一次；若全域 → 一次性

**Step 7（charter_version）**：每個專案的 `agent-commons/_config/profile.yaml` 都要改

**Step 8-9（驗收）**：每個專案各跑一次

### Q2: 我是 Enterprise tier 不必動、但想拿 Antigravity 新功能怎麼辦？

跑完本 walkthrough Step 2-9 即可、Step 0.1 表第二行（Enterprise）不必動 = 你還是有 Gemini CLI 作為 fallback、同時可選用 Antigravity 拿新功能。

### Q3: 我升 0.11.0 後想退回 0.10.6 怎麼辦？

charter v0.11.0 對 0.10.6 是 **新增 vendor spec、不刪既有**（gemini-cli.md 標 LEGACY 但保留全部內容）— 你可以：

1. `profile.yaml` `charter_version: "0.10.6"`
2. 繼續用 Gemini CLI（若你的 tier 還能用）+ 原 `.gemini/commands/*.toml`
3. 跳過 `~/.gemini/skills/<name>/SKILL.md`（Antigravity 用、Gemini CLI 不讀）

→ charter v0.11.0 升 v0.10.6 是 **lossless reversible**。

### Q4: Antigravity 沒有對應的 disable sub-agent 指令、怎麼辦？

依 `roles/pm/antigravity-cli.md §3.5.5` 處置：
1. 跑 `agy --help` / 查 `antigravity.google/docs` 確認 Antigravity 對應指令名（path A 預估 `/agents disable generalist`、待 LIVE 校正）
2. 找到對應指令 → 跑 disable
3. 找不到 → 紀錄為已知 vendor gap + PM self_audit 加額外項

回報 maintainer 你實測的指令名、幫 charter LIVE 校正 `antigravity-cli.md §3.5.5`。

### Q5: 我的 underlying model 想用 Claude 不用 Gemini 怎麼辦？

Antigravity 是 multi-model vendor、可在 session 內 `/model claude-sonnet-4-6` 切到 Claude — 對應 charter A1 公理 vendor tool ⊥ underlying model 雙軸分解。PM 行為依 `antigravity-cli.md` 規範、underlying model 由你選。

或編 `~/.config/antigravity/config.toml` pin 預設：

```toml
model = "claude-sonnet-4-6"
```

### Q6: 跨多版升（例如 v0.9.x 直接升 v0.11.0）怎麼辦？

兩步走：
1. 先依 `examples/upgrades/v0.9.x-to-v0.10.0.md` + `examples/upgrades/v0.10.1-to-v0.10.2.md`（BREAKING-LITE）+ ... 累積到 v0.10.6
2. 再跑本 walkthrough v0.10.6 → v0.11.0

跨版升 = 累積、charter 不破壞向下兼容。
