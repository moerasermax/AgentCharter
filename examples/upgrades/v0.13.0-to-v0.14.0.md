# Walkthrough: v0.13.0 → v0.14.0 升版（可選 Governance Profile）

> **適用**：採用方 charter_version 為 `0.13.0`，準備升到 `0.14.0`
> **核心改動**：四條 opt-in core 條款、governance overlay 與參數化 PreToolUse guard 範例
> **預估時間**：只升版本約 5 分鐘；採用 overlay／部署 guard 另行評估
> **向下兼容**：不開 overlay 時行為不變；既有 preset 與強制必啟集合不增加 governance 要求

---

## 0. 升版前確認

確認採用方 `<common-memory-root>/_config/profile.yaml` 的版本與 preset；備份 profile，列出預計修改的目標。取得 v0.14.0 framework 檔案後，確認 `tools/profiles/governance.overlay.yaml` 與四個新 core 檔存在。

## 1. 只升版，保持既有行為

局部更新採用方 profile 的版本：

```yaml
charter_version: "0.14.0"
```

不加入 governance overlay；四個新條款未設定時均為 false。原有條款與 `_required.yaml` 仍生效，無需部署 PreToolUse hook。

## 2. 可選：採用 Governance Overlay

依 [charter-config §7.1](../../core/charter-config.md) 將 overlay 結構化合併到實際 profile。先載入原 preset，再合併 overlay、當前 vendor 覆寫與採用方局部覆寫；不取代 preset，不改 `_required.yaml`，合併後將有效值寫入 profile。可用 `overlays: [governance]` 記錄來源，但它不是自動載入器。

```yaml
version: "0.4.0"
charter_version: "0.14.0"
preset: standard
overlays: [governance]
enabled:
  work-budget: true
  subagent-gating: true
  human-gates: true
  execution-routing: true
```

以上僅為啟用片段，參數必須從 overlay 合併，不可漏貼後宣稱已完整採用。核對實際 vendor、預算口徑、Evidence／compact／tool output 控制。`ask_executor_per_task` 預設 false，只有採用方明確設 true 才改變任務開頭的執行者選擇流程；啟用時人選擇優先於 PM 的執行者分派，角色權限維持既有規則。

## 3. 可選：部署 Guard 範例

先讀 [規格與已知限制](../../tools/pretooluse-guard-spec.md)，再複製 [腳本](../governance-profile/global_guard.example.ps1) 與 [設定](../governance-profile/guard-config.example.json) 至採用方核准位置。以 `-ConfigPath` 指向設定，依 host 實際 hook 契約接入。範例為正則黑名單、非安全邊界；部署屬配置變更，須先取得人工核准。

不要把 overlay 當作 hook 安裝器；範例不自動設定環境變數、不安裝 hook、不保護自身或計並行數。核准通道須由人控制，不能由 AI 自行設定再啟動 CLI 取得授權。

## 4. 升版後驗證與回退

- **未採用 overlay**：確認四條未啟用，原 preset 與必要條款保持原值。
- **已採用 overlay**：核對四條啟用、合併順序與實際 vendor 參數；核准工作包額度優先於預設。
- **已部署 guard**：隔離測試允許／拒絕事件與 host 實際阻擋，依規格交付真實 stdout；沒有測過即標尚待確認。
- **回退可選功能**：人工核准後移除四條有效啟用值或設 false，移除對應參數／來源標記並停用另行部署的 hook；保留原 preset 與強制必啟值。

此版本未新增 overlay 載入器或 vendor 設定寫入器；配置解析與 hook 部署由採用方既有流程完成。
