## 常見問題

### Q1: 我跑 migration script 失敗怎麼辦？

依 script 提示處理：
- `git status` 不乾淨 → commit 或 stash 後重跑
- `agents-commons/` 已存在 → 手動檢查、可能上次 migration 部分完成、考慮 `git restore` 重來

### Q2: agents-commons rename 後我的 vendor slash command 內路徑會自動更新嗎？

migration script Step 3 sed 會掃 `.md/.yaml/.toml/.sh/.py/.js/.ts/.cjs/.ps1` 檔案內 `agent-commons/` → `agents-commons/`、包含採用方端 vendor command。但**建議重 self-instantiate** 以對齊 canonical layer + adapter（依 Step 5）。

### Q3: 我只想 ship agents-commons rename、不要 SSS S2.5 canonical layer / Antigravity vendor 接入怎麼辦？

技術上可以、但不推薦（會 charter_version 處於中間狀態 0.11.x、不對齊任何 release）。建議走 v0.10.6 → v0.11.0（Antigravity vendor only、見 `v0.10.6-to-v0.11.0-antigravity-migration.md`）+ 暫不升 v0.12.0、等下次 release 再一起升。

### Q4: SSS S2.5 canonical init-spec layer 對既有 vendor command 影響？

既有 vendor command（v0.11.0↓ self-instantiated）仍可運作、不會 breaking。新加 W1301（跨 vendor 深度偏差）只是 advisory warning、不 reject。但建議重 self-instantiate 對齊 canonical 6 段格式、長期一致性更好。

### Q5: agents-commons rename 違反 v0.5.9「永不破壞既有採用方」承諾、為什麼？

對齊 `core/versioning-migration §2.3.5` 衝突釋疑：違反 letter（改名）但對齊 spirit（提供 migration script 痛點低、v0.x 階段彈性條款允許）。自 v0.12.0 起 `agents-commons/` 結構為 v1.0+ 永久承諾、不再 rename。

### Q6: 跨多版升（例如 v0.9.x 直接升 v0.12.0）怎麼辦？

依 `core/versioning-migration §3.4`：先升 v0.10.0 → v0.10.6（依各歷史 walkthrough）→ 再跑本 walkthrough v0.10.6 → v0.12.0。
