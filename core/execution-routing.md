# Execution Routing（單一模型路由與派工紀律）

> **狀態**：v0.1
> **位階**：core 通用條款（opt-in，governance overlay）。
> **依存**：`charter-config.md`（啟用與參數）；角色責任交叉引用 `role-separation.md`，證據上限交叉引用 `work-budget.md`。
> **保證強度**：單 actor 自律（路由選擇、可用性驗證與輸出判讀依賴 LLM 紀律）
> **檢測時點**：runtime + handoff
> **since**：v0.14.0

---

## 0. 啟用與位階

僅在 `enabled.execution-routing: true` 時生效；缺值視為 false。effort 與詢問執行者的選項見 [governance overlay](../tools/profiles/governance.overlay.yaml)，`ask_executor_per_task` 預設 false。

## 1. 條文

| 面向 | 合規規定 |
|---|---|
| 唯一派工入口 | 主導者先定義工作包、證據與驗收，再透過單一模型路由器派工；不得在 hook 建立第二套路由器。主導者自己執行不算另建派工入口。 |
| 責任分工 | 會話與提醒服務只保存提醒、session 摘要、決策與未完成事項，除非實際能力已驗證，不宣稱具備任務分類、風險／預算決策。事實庫保存跨 session 已查證結論：先搜尋，只讀相關原文，確認後才寫回。 |
| 模型可用性 | 靜態清單或 fallback 不單獨證明可路由；選用前核對即時能力與失效資訊。本地／輕量 provider 未實際確認即標「尚待確認」。 |
| effort | 每次派工明傳 effort，不依賴 CLI 預設。日常使用 profile 的一般級別；提高級別僅限跨模組、架構、高風險修改、歧義或一次一般級別產出不足；更高級別須人明確要求。vendor 不支援時回報，不假裝已套用。 |
| 輕量工作 | 分類、摘要、查詢改寫與 log 整理優先使用已確認可用且資料可外送的本地／輕量模型。 |
| 資料與 provider | 機密、個資與保密協議內容不得送往未核准 provider；可用與可外送分別驗證。 |
| 交叉驗證 | 只驗高風險 claim 或實際分歧；第二模型讀精簡 Evidence 包與第一模型的可檢驗 claim，不重掃同批檔案；Evidence 上限依 `work-budget.md` 的 profile。 |
| 路由結果 | exit 0 仍須驗證輸出非空且符合交付契約；空內容不是成功。失敗依 `work-budget.md` 停止，不換模型原樣重跑。 |
| 帳號額度判讀 | 若路由需要參考帳號額度，對照來源原文的「已用／剩餘」、單位、視窗與時間；不得依欄位名稱或百分比猜語意。量不到為 unknown，不得宣稱「還夠」；帳號用量不納入工作預算。 |
| 品質 | 高風險結論附 Evidence、Confidence 與尚待確認事項；回報區分已觀察／合理推論／尚待確認，不因節省額度省略關鍵證據、反例、測試或人工 review。 |

### 1.1 可選：任務開頭選執行者

僅 `parameters.execution-routing.ask_executor_per_task: true` 時，實作、修 bug、分析等任務開頭讓人選：① 模型路由器（附建議模型與 effort）② 本 session 主導者 ③ 自動（由主導者選擇並說明理由）。同一任務的重派與修正沿用選擇，換任務才再問；人已指定時不重問。

PM 仍負責任務契約、角色分工與驗收安排；本選項決定執行載體，不授予角色權限。啟用時人選擇優先於 PM 的執行者分派；專案模型建議只作選擇參考。未啟用時維持既有 PM 分派流程。

## 2. 設計動機

單一路由入口讓可用性、成本判讀與資料外送政策有一致位置；會話服務、事實庫與機械護欄各守責任，避免能力被文字描述虛構。

## 3. 反例

- ❌ CLI 預設較低 effort，派工省略參數卻宣稱使用一般級別。
- ❌ 路由 exit 0 但輸出空白，主導者仍回報已完成。
- ✅ 第二模型只驗高風險 claim，附來源與未決點，不重新掃 repository。

## 4. 範例：參考實作

模型路由器的參考實作為 [ai-cli](https://github.com/moerasermax/tkflyc-ai-cli)；事實庫的參考實作可採 `knowledge` MCP，會話與提醒服務則由採用方選擇已驗證的實作。這些名稱只用來辨識參考實作，不是依存、安裝要求或功能驗證證據；採用前自行核對可用性。
