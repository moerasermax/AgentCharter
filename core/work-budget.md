# Work Budget（工作預算與停止條件）

> **狀態**：v0.1
> **位階**：core 通用條款（opt-in，governance overlay）。
> **依存**：`charter-config.md`（啟用與參數）；升級與分類交叉引用 `escalation-protocol.md`、`failure-modes.md`，不另定義階梯或 F-mode。
> **保證強度**：單 actor 自律（計數與停止依賴 LLM 紀律；環境壓縮由執行環境負責）
> **檢測時點**：runtime + handoff
> **since**：v0.14.0

---

## 0. 啟用與位階

僅在 `enabled.work-budget: true` 時生效；缺值視為 false。數值與 vendor 差異見 [governance overlay](../tools/profiles/governance.overlay.yaml)，已核准工作包的額度優先於 profile 預設。

## 1. 條文

| 面向 | 合規規定 |
|---|---|
| 工作預算 | 工作包先列搜尋輪數、工具呼叫次數、讀取檔案數、修改檔案數、測試／修正輪數；由 profile 或人工核准額度決定上限。未核准不得自行擴大。 |
| 達限 | 達任一工作預算先回報「已完成／未完成／需追加額度」，取得同意後續推。已核准工作包依核准額度，不以 profile 預設重新限縮，也不得把追加額度解讀為其他高風險操作的授權。 |
| 連續失敗 | 同一工具或同一假設連續失敗達 profile 門檻即停止該嘗試，回報已試內容、錯誤、未知事項與最小下一步；範例 profile 的門檻為連續兩次。不得無限重試、換模型原樣重跑或擴大掃描；升級須帶失敗證據與新理由。 |
| 範圍變動 | 任務邊界變動先回報，依 `human-gates.md` 取得人工核准後重訂工作包，不把新目標塞進原額度。 |
| 定位與去重 | 優先用 `rg`、既有摘要、事實庫與 Evidence 索引；不無差別掃描 repository，不重讀內容未變且已有可用摘要的檔案。 |
| 證據輸出 | 長 log 先本地定位與過濾，只回傳必要段落；完整證據依採用方既有保存機制留存。單一 Evidence Block 的 token 目標上限見 profile，不得以壓縮省略關鍵證據、反例、測試或人工 review。 |
| 上下文控制 | compact 門檻與工具輸出上限是執行環境設定，不是工作額度；達上下文門檻由環境壓縮，交接需保留來源與未完成事項。若 vendor 要求停止，依 vendor 覆寫停止回報。 |
| 帳號用量 | 帳號配額、計費與平台扣量不由本條款管理，不得拿工作預算或 compact 數值冒充帳號上限。 |

### 1.1 計數口徑

一輪搜尋是針對同一定位問題的一組查詢；工具呼叫按實際送出的呼叫計次，批次包裝不消除內含呼叫。讀檔／改檔按工作包內不重複路徑計數；重讀仍消耗工具次數。一次測試／修正輪包括一次驗證與因該結果必要的修正。採用方可調整口徑，但須在工作包開始前寫明，不可事後改口徑規避達限。

## 2. 設計動機

工作量、上下文大小與帳號用量解決不同問題。分開設定讓跨 vendor 採用方保留深度分析品質，又能在邊界變動或無效嘗試時作出可審查的續推決定。

## 3. 反例

- ❌ 工具已達限，改由另一模型重跑同一命令，稱為「新的預算」。
- ❌ compact 門檻當作帳號還可使用的 token 餘額。
- ✅ 失敗達門檻後附錯誤與新假設，申請明確追加額度。

## 4. 與其他條款的關係

本條款的停止是執行嘗試／工作量邊界，不等同偏差退稿。[升級協議](./escalation-protocol.md) 的強化抽驗與使用者裁決階梯、[失敗模式](./failure-modes.md) 的 F1〜F6 分類維持原定義；工具錯誤不自動等於違規。Evidence 的觀察／推論區分見 [evidence-first](./evidence-first.md)。
