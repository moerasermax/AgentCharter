# Human Gates（人工確認與範圍閘門）

> **狀態**：v0.1
> **位階**：core 通用條款（opt-in，governance overlay）。
> **依存**：`charter-config.md`（啟用）；整合宣告交叉引用 `structural-anti-fabrication.md`。
> **保證強度**：單 actor 自律；部署 guard 時，已列黑名單動作部分為結構強制（非安全邊界）
> **檢測時點**：runtime + handoff
> **since**：v0.14.0

---

## 0. 啟用與位階

僅在 `enabled.human-gates: true` 時生效；缺值視為 false。不取代既有角色權限、採用方安全政策或已生效的人工閘門。

## 1. 條文

| 動作類別 | 合規規定 |
|---|---|
| 資料破壞 | 刪除／覆寫資料前取得人工確認，提供目標、影響與備份／復原方式；不把一般任務授權推導成任意破壞授權。 |
| 破壞性 Git | 重設、清除、強制推送等可能丟失資料或改寫歷史的操作須人工確認精確範圍。 |
| 秘密檔 | 秘密、憑證或環境秘密檔寫入須人工確認；核准回報不複製秘密內容。 |
| 系統與外部影響 | 權限、網路、部署變更、開放 Port 須人工確認。 |
| 全域配置 | 全域設定整檔覆寫須人工確認，保留既有可用配置，優先結構化合併。 |
| 安裝 | 安裝套件／plugin／MCP 須人工確認，不以「實作方便」自行安裝。 |
| 範圍擴張 | 擴大任務、非必要重構或修改未授權 repository 須人工確認新工作包。 |
| 修改準備 | 修改前列出目標檔案並備份；對配置採結構化合併，避免整檔替換。新增檔無舊內容可備份時明示，備份依採用方政策放置。 |
| 未驗證整合 | 未在環境中找到並驗證的腳本或整合不得宣稱「已接軌」；先交付現有工具能產生的可追溯 Evidence，再由人決定導入方式。 |

具體目標與影響已獲人工核准時，沿用該核准，不重複詢問；範圍、風險或目標改變時須更新核准。無法確認核准範圍即標為尚待確認，停止依賴該核准的動作。

## 2. 設計動機

讓人核准可審查的結果與影響，避免模糊授權、秘密外洩與配置損失。guard 只能攔已列形式；未命中黑名單仍有人工確認義務。

## 3. 反例

- ❌ 為執行測試自行安裝系統套件並開放網路 Port。
- ❌ 只讀到整合文件便宣告部署完成。
- ✅ 先列目標與備份，再交付局部合併差異；未驗證整合標為尚待確認。

## 4. 與其他條款的關係

[structural-anti-fabrication](./structural-anti-fabrication.md) 定義宣告必備證據，不因取得核准而免除；[PreToolUse guard](../tools/pretooluse-guard-spec.md) 的黑名單僅涵蓋本清單部分形式，不保證阻止所有高風險動作。
